# QA: --load and --load-info Parameters

## Overview

This document captures open questions, unclear issues, and contradictions that need to be resolved before implementing the `--load` and `--load-info` parameters.

---

## Requirements Summary

1. **`--load <path>`**: Acts like `--resume` or `/load <path>` in the chat REPL. Loads a saved.json file.
2. **`--load` overrides `--resume`**: When both are specified, `--load` takes precedence.
3. **`--load-info <path>`**: Prints statistical information about the file loaded via `--load` or `--resume` and exits.
4. **`LAMA_OLE_LOAD` env var / config**: `--load` can also be specified via this environment variable or config file.
5. **`--load-info` is CLI-only**: Cannot be applied via environment variable or config.
6. **Model mismatch prompt**: The mechanism from `--resume` (asking user to choose between session model and CLI model) should also apply to `--load` and `/load`.

## Contradictions and Ambiguities

### C1: `--load` vs `--resume` Semantics

**Issue**: The requirements say `--load` "acts like `--resume` or `/load saved.json`". These three have different semantics:
- `--resume`: Auto-resumes the most recent session for the current directory.
- `/load <path>`: Loads a specific session file from the chat REPL.
- `--load <path>`: New parameter, should it behave more like `--resume` (auto-detect) or `/load` (explicit path)?

**Resolution needed**: Clarify whether `--load` requires an explicit path or can work without one (auto-detect like `--resume`).

AC1: `--load` requires an explicit path .

### C2: Model Mismatch Prompt Scope

**Issue**: The requirements state the model mismatch mechanism should apply to `/load` and `--load`, but the current implementation only triggers it in `_resume_session_into()`. 

**Resolution needed**: Determine if the prompt should trigger for ALL session loads (including `/load`) or only for `--load` and `--resume` at startup.

AC2: The prompt should trigger for ALL session loads.

### C3: `--load-info` Scope

**Issue**: The requirements say `--load-info` "prints out statistical information about the file which is loaded via `--load` or `--resume`". This is ambiguous:
- Does it print info about the file specified by `--load`?
- Does it print info about the file that `--resume` would load?
- Does it print info about both if both are specified?

**Resolution needed**: Clarify the exact behavior of `--load-info` when used with `--load`, with `--resume`, or with neither.

AC3: --load-info is renamed to --stats. --stats prints info about the file specified by `--load` or about the file that `--resume` would load. When neither is given it exits with an error message that --load or --resume has to be set.


### C4: Environment Variable Name Confusion

**Issue**: The requirements mention `LAMA_OLE_LOAD` but the existing pattern uses `LAMA_OLE_RESUME` for `--resume`. Should we follow the same pattern (`LAMA_OLE_LOAD` for `--load`)?


**Resolution needed**: Confirm the exact environment variable name and whether it should follow the `LAMA_OLE_*` naming convention.

AC4: yes. `LAMA_OLE_LOAD` and `--load` gets a parameter, `LAMA_OLE_RESUME` and `--resume` doesn't.

### C5: One-Shot Mode Behavior

**Issue**: The requirements don't clarify whether `--load` should work in one-shot mode (without `--chat`).

**Resolution needed**: Determine if `--load` is chat-only or if it should also work in one-shot mode, and if the latter, how the loaded messages should be processed.

AC5:  `--load` works only in chat mode.
