# Fix: Include Thought Data in NDJSON Logs

## Proposed Solution
To ensure that the model's reasoning/thinking process is captured in the `--logndjson` output, we need to modify how assistant messages are constructed and logged within `tool_base/engine.py`.

Currently, `response_content` only accumulates `msg.content`. We should also accumulate `msg.thinking` into a separate buffer or combine them so that the final assistant message includes both.

## Implementation Plan

### 1. Modify `run_with_tools` in `tool_base/engine.py`
The loop that processes the model stream needs to be updated:

- **Initialize a thinking buffer**: Create a variable (e.g., `response_thinking = ""`) at the start of the response processing block.
- **Accumulate thinking chunks**: Inside the chunk iteration, if `msg.thinking` is present, append it to `response_thinking`.
- **Update Assistant Message Construction**: 
    - When an assistant message is created (either when tool calls are detected or at the end of the stream), combine `response_content` and `response_thinking`.
    - A recommended format for the combined content would be:
      ```python
      combined_content = ""
      if response_thinking:
          combined_content += f"<thought>\n{response_thinking}\n</thought>\n\n"
      combined_content += response_content
      ```
    - This ensures the `assistant_msg` sent to `ndjson_log_file_handle` contains the full context.

### 2. Refine Message Construction for Tool Calls
When tool calls are detected, the current code creates an `assistant_msg` using only `response_content`. It must be updated to use the combined content (including thinking) so that the reasoning leading up to the tool call is preserved in the log.

### 3. Verification Steps
- **Manual Test**: Run a model known to support thinking (e.g., DeepSeek R1 via Ollama). Use `--logndjson` and verify that the resulting JSON lines for `assistant` roles contain the `<thought>` block.
- **Regression Check**: Ensure that models without thinking capabilities still produce valid NDJSON logs with standard content.
- **Format Consistency**: Verify that the combined string doesn't break any downstream parsers (though standard text/newlines should be fine).

## Expected Result
The `--logndjson` file will now contain a complete history of the conversation, including the model's internal reasoning process before it produces an answer or calls a tool.
